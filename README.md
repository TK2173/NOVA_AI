# NOVA AI — стартовый проект

Адаптивный чат на русском языке с прикреплением изображений. Проект подготовлен для публикации на Render через `render.yaml`.

## Быстрая публикация (Render)

1. Создай репозиторий на GitHub и загрузи в него **содержимое этой папки** (включая `render.yaml`), не загружая `.env` и секретные ключи.
2. Открой https://render.com/ и войди/создай аккаунт.
3. В Render выбери **New → Blueprint**, подключи репозиторий и подтверди создание сервиса `nova-ai`. Конфигурация берётся из `render.yaml`; сервис использует бесплатный план.
4. После создания у сервиса появится публичный адрес `https://...onrender.com`. Первый запуск может занять несколько минут.
5. Чтобы работал именно ИИ-чат, в настройках сервиса Render открой **Environment** и задай три переменные от выбранного OpenAI-совместимого провайдера:
   - `AI_BASE_URL` — полный URL Chat Completions endpoint провайдера;
   - `AI_MODEL` — точное название модели, которая поддерживает изображения, если нужна загрузка фото;
   - `AI_API_KEY` — секретный API-ключ.
   Затем нажми **Save, rebuild, and deploy** (или аналогичную кнопку redeploy). Не вставляй ключ в HTML, сообщения или публичный GitHub-репозиторий.

**Важно:** хостинг сайта и доступ к ИИ-модели — разные вещи. Render размещает сайт, но не предоставляет автоматически бесплатную ИИ-модель. Бесплатная квота у AI-провайдера может иметь лимиты и меняться. До ввода ключа страница может открываться, но ответы ИИ не заработают. Не используй адрес локального Ollama (`127.0.0.1`) на облачном сервере — это адрес самого сервера Render, а не твоего компьютера.

Render Free засыпает после периода бездействия, поэтому первый запрос после паузы может открываться медленно. Бесплатный тариф предназначен для тестов и хобби-проектов, не для гарантированной круглосуточной работы.

---

## Важно про «бесплатно и без ограничений»

- **Локальный режим:** запросы к модели не оплачиваются за токены, но нужны компьютер/сервер, электричество, память и достаточно мощное оборудование. Скорость и качество зависят от модели и устройства.
- **Публичный сайт:** если другие люди должны пользоваться ИИ через интернет круглосуточно, модель должна работать на доступном сервере. Бесплатные хостинги и облачные AI-провайдеры имеют лимиты, могут засыпать или менять условия.
- Не обещай пользователям бесконечный доступ, пока у тебя нет ресурсов для этого. В проекте включён базовый лимит запросов на IP.

## Вариант A: запустить бесплатно на своём компьютере с Ollama

1. Установи Node.js версии 20 или новее: https://nodejs.org/
2. Установи Ollama: https://ollama.com/
3. Открой терминал и скачай vision-модель (пример):
   ```bash
   ollama pull qwen2.5vl:3b
   ```
   Эта модель — пример для старта, а не гарантия лучшего качества. Если компьютер слабый, ответы могут быть медленными.
4. Скопируй `.env.example` в `.env`. Настройки по умолчанию используют локальный Ollama:
   ```env
   AI_BASE_URL=http://127.0.0.1:11434/v1/chat/completions
   AI_MODEL=qwen2.5vl:3b
   AI_API_KEY=
   PORT=3000
   ```
5. В папке проекта выполни:
   ```bash
   npm install
   npm start
   ```
6. Открой http://localhost:3000

Если модель не отвечает, проверь, что Ollama запущен и модель скачана. Некоторые модели/версии могут по-разному поддерживать OpenAI-совместимый формат изображений; если фото не работает, проверь актуальную документацию Ollama или используй провайдера, который явно поддерживает vision и OpenAI-compatible Chat Completions.

## Вариант B: подключить облачную vision-модель

1. Создай ключ у выбранного провайдера.
2. Укажи в `.env` его документированный endpoint и название модели:
   ```env
   AI_BASE_URL=https://provider.example/v1/chat/completions
   AI_MODEL=vision-model-name
   AI_API_KEY=your-secret-key
   ```
3. Не помещай ключ в `public/index.html`, не добавляй `.env` в Git и не отправляй ключ пользователям.
4. Проверь цены, бесплатную квоту, условия обработки данных и ограничения модели до публикации. Бесплатная квота не означает безлимитное использование.

## Что реализовано

- Адаптивный интерфейс для телефона и компьютера.
- Русский чат и простая история текущего диалога в памяти страницы.
- Прикрепление одного изображения JPEG/PNG/WEBP/GIF до 5 МБ.
- Передача изображения модели как data URL без постоянного хранения на сервере.
- API-ключ хранится только в серверном `.env`.
- Ограничение частоты запросов: 20 запросов на IP за 15 минут.
- Базовые ограничения длины текста, размера и типа изображения.

## Перед публикацией

Это starter-проект, а не полностью готовый production-сервис. Перед открытием для публики добавь:
- HTTPS и безопасное размещение переменных окружения;
- настоящую аутентификацию, если нужна история между устройствами;
- общий бюджет/лимиты расходов у провайдера и мониторинг;
- более строгую защиту от злоупотреблений, CAPTCHA при необходимости и ограничение затрат;
- политику конфиденциальности, сроки хранения и понятное согласие на обработку запросов;
- тесты, журналирование без записи содержимого чатов и обработку сбоев.

Не публикуй локальный Ollama endpoint напрямую в интернет без продуманной защиты. Вложения обрабатываются в памяти и не сохраняются в файловую систему проектом, но отправляются выбранному AI-провайдеру для ответа.


## Безопасность контента (базовый слой)

Добавлен `moderation.js`:
- системные инструкции для модели: не помогать с терроризмом, экстремистской вербовкой/пропагандой, призывами к насилию и практическими инструкциями для преступлений;
- базовая проверка явных опасных формулировок на входе и отдельных опасных шаблонов на выходе;
- нейтральные образовательные, исторические, новостные и профилактические вопросы не должны автоматически запрещаться только из-за упоминания темы.

**Ограничение:** регулярные выражения не понимают контекст и могут пропустить перефразированный запрос или ошибочно заблокировать безопасный. Модель также может нарушить системные инструкции. Для публичного запуска добавь независимую модерацию запросов и ответов (модель/сервис модерации), тесты на русском и других языках, ручной процесс жалоб и обновление правил. Не заявляй, что сайт гарантированно соблюдает все законы РФ: это требует юридической проверки актуальных требований к конкретному сервису, аудитории, данным и месту размещения.
